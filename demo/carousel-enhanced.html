Challenges & Solutions

Hard problems, real solutions.

Challenge
Historical FX rates weren't always available for the exact transaction date
→
Solution
3-tier fallback chain: fx_history (exact date) → fx_rates (latest) → 1.0 + warning log
Challenge
AI-generated insights became repetitive and predictable over time
→
Solution
Deterministic daily lens rotation (7 analytical perspectives, e.g., CFO mode, anomaly detection)
Challenge
Market data APIs would fail intermittently, wiping portfolio valuation
→
Solution
Graceful degradation: skip failed assets, keep existing data. Never DELETE on API error
Challenge
Dashboard privacy — showing sensitive amounts in public spaces
→
Solution
Optimistic UI privacy toggle — blur all amounts instantly, sync to server in background with no flicker

Key Engineering Takeaways

What this project reinforced.

Principles that show up in every serious data system
✓

Reliability over cleverness

Fallback chains, retry with backoff, and graceful degradation matter more than clever architecture. Systems fail — design for it explicitly.

✓

Normalize data at ingestion time

Computing amount_idr server-side at write time — not at read time — is the difference between fast queries and slow ones at scale.

✓

AI is a pipeline component, not magic

LLMs need input validation, output schemas, fallback classifiers, caching, and cost controls — just like any other service in your stack.

✓

Observability from day one

Dual-sink writes (portfolio_snapshot + wealth_ledger_daily), freshness SLAs via last_updated_at, and reconciliation cron jobs — not afterthoughts.

08 / 10
Lessons Learned

What building this actually taught me.

01
Clean schema design saves more time than any optimization. Getting the FX normalization model right early meant never rewriting the query layer.
02
Prompt engineering is software engineering. The NLP parser works because the system prompt is structured, tested, and versioned — not because GPT-5-mini is magic.
03
Real-time UX requires explicit tradeoffs. Optimistic updates, Supabase Realtime subscriptions, and background syncs each solve different user experience problems.
04
Automation surfaces data quality issues fast. Running the snapshot cron the first week revealed 3 normalization bugs that would have been invisible in a manual workflow.

Building end-to-end systems taught me that architecture decisions at the data layer ripple through every layer above it — and fixing them later costs 10× more.
